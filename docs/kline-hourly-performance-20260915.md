## 就绪与请求完成的差距

八次整点中，每次均有 718 个合约、491 个现货收盘到齐。逐小时核对了 `expected=arrived=n=ev_n`、客户端计数之和、最晚 ready 明细与汇总的一致性；统计溢出和丢弃为 0。合约全部 ready 的范围为 T+150.542–217.644ms，现货为 T+112.037–277.106ms。绝对偏移包含服务校时与上游到达时间的影响。

01:00 合约已经在 T+154.742ms 全部 ready，但最后一条 `BULK_FINAL_WAIT` 到 T+668ms 才打印；04:00 分别为 T+217.644ms 与 T+642ms。所有记录到的等待最终 `pending_after=0`。`waited_ms` 包含线程恢复执行的等待，不能将额外耗时都解释为等待上游收盘消息。

01:00 两个 bulk 接口的 p50 都为 575ms，资金费率 p99 也达到 635ms。因此 HTTP 请求处理与共享资源竞争仍需继续定位。现有记录不足以把每次波动分配给 JIT、线程调度或锁等待。
