# Java 单币价格优先读取内存

2026-09-29 修改，已部署 Java 1.8.3 到 `market.feng.dog`（`45.76.207.137`）。

`/fapi/v1/ticker/price?symbol=...` 和 `/api/v3/ticker/price?symbol=...` 先读取该币种本地 K 线缓存的最新 close，内存命中不获取 REST 额度、不请求币安。现货 `symbols` 参数只选择一个币种时，也使用同一规则。

按照订阅周期的配置迭代顺序查找；某周期还未初始化或序列为空时，继续检查其他已订阅周期。没有配置周期时沿用原有 1h 默认值。只有这些周期都没有该币种的实际缓存记录，才调用原有 REST 单币价格接口，并保留原权重、限流、错误传播及响应格式。

这次复用 Java 已有的 K 线内存取价逻辑，没有增加一份价格缓存或新的后台订阅。形成中 bar 更新后，下一次查询直接读取新 close；不受 bulk 响应缓存 TTL 影响。缓存查询只读，不插入空序列、不触发 K 线补历史。

## 返回值语义

- 价格来自缓存中的最新实际 K 线 close，沿用 string / float / double / bigDecimal 数值模式。
- 按本次要求，已有记录就优先读取，不因其年龄额外触发即时 REST；断线期间可能返回最后已知价格。
- 合约 `time` 沿用 Java 原内存兜底逻辑的查询时刻，不保证等于官方 REST 的最后成交时刻。现货继续不输出 `time`。REST 回退返回官方原始价格与时间。
- 没有 symbol 的全市场价格、现货多币种价格、24h ticker 和 K 线/bulk 逻辑保持既有行为。
- 未建立 K 线缓存的币种仍会走 REST；此次不将 REST 单币报价伪造为 K 线写回。
