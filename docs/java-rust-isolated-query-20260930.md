**当前 Java / Rust 查询性能同机对照｜2026-09-30**

比较 Java 1.8.9 与 Rust 0.4.22 当前 HTTP 查询实现。在相同服务器、相同数据、相同请求和充分预热的条件下，测量数据已经在内存时的调用表现。以下结果不再使用此前两台生产 VPS 的耗时倍数。

| 200 客户端同时请求；单位 ms | Java p50 | Rust p50 | Java p99 | Rust p99 | Java p99 多耗时 | p99 Java/Rust |
|---|---:|---:|---:|---:|---:|---:|
| 合约 bulk，5 币 × 10 根 | 10.14 | 6.62 | 40.68 | 17.42 | +23.26 | 2.34 倍 |
| 合约单币 K 线，10 根 | 7.70 | 4.74 | 18.06 | 11.83 | +6.23 | 1.53 倍 |
| 现货单币 K 线，10 根 | 7.70 | 5.28 | 15.72 | 14.24 | +1.48 | 1.10 倍 |
| 资金费率 → bulk，两步完整链 | 25.03 | 15.98 | 74.08 | 30.47 | +43.61 | 2.43 倍 |
| 资金费率 → bulk → 3 次单币，五步完整链 | 75.36 | 46.40 | 117.67 | 65.67 | +52.01 | 1.79 倍 |

单币两行同样是 200 客户端同时请求，不代表低并发单次调用；两步、五步是从该客户端第一步发出到最后一步读完的完整耗时，并非各步骤 p99 相加。每种场景每版各 8,000 条请求或完整链。

**测量边界**

服务端固定为东京测试实例 45.76.207.27（2 vCPU Skylake，约 2 GiB 内存），每次只运行一个版本。客户端固定为 45.76.207.137，使用独立进程，不占用被测服务器 CPU。直连同一个 TCP 18088 端口，HTTP/1.1 长连接、无压缩，绕过 Nginx/TLS。网络路径相同，但表中的 HTTP 延迟仍含共同的 TCP 往返与客户端调度，不能当作纯函数执行耗时。客户端位于 Java 生产 VPS，客户端自身可能存在背景竞争；未声称排除所有网络或虚拟机噪声。

Java 加载线上 1.8.9 JAR 中的控制器和服务，保留 Spring Boot/Tomcat/Spring MVC、虚拟线程、线上 JDK 21.0.2 及 -Xms1g -Xmx2g -XX:+UseG1GC。Rust 使用 0.4.22 当前 crates 的 Axum/Engine/市场 API，release 构建、2 个 Tokio 工作线程；部署记录中的 16 个改动文件 SHA 与当前源码一致。双方都由专用测试入口注入固定时钟、固定数据和受计数的上游替身；这不是直接启动两个完整生产服务。

输入包括 739 个合约和 496 个现货 symbol。返回的最近 10 根 closed 1h 来自当前服务真实数据；每序列另外补齐 990 根较早的占位历史，保持两版相同的 1,000 根容量，这些占位行从不被请求。资金费率使用相同的最近 4 小时已缓存结果。Java 没有现货 bulk 路由，因此只对比双方均支持的接口。

按 Java A → Rust A → Rust B → Java B 顺序运行。每个进程先为全部五类场景各预热 40 波，再在正式阶段每类另预热 10 波并测量 20 波，每波 200 客户端；客户端以确定性种子选择分散 symbol，双方请求逐条配对。进程禁止 swap，后台以 0.5 秒采样监测内存和宿主机；JFR/perf 等重型分析器未参与正式测量。

本轮回答“数据已就绪时，当前实现处理同样调用的差距”。没有重放实时 WebSocket 更新、定时订正、snapshot、整点新 bar 到达或生产额外流量，因此不能据此断言整点数据准备耗时、完整生产内存占用，或任何负载下的性能上限。线上两个生产进程没有被替换或重启。
